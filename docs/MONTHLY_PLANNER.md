# 月度理财工作台工程契约

本文件是主应用内「月度理财」功能的产品与工程契约，供实现、评审与验收使用。
文中不含任何个人账户、金额或本机路径；真实私人参数只在用户本机的私人配置里维护。

## 1. 定位与边界

- `WealthGrowthTracker / 月度理财` 是主应用内的一个工作台，不是第二个应用、第二套登录或第二套总账。
- 与现有实体分离：月度会话键为 `monthly-planning:YYYY-MM`，自然月财务报告键为 `monthly:YYYY-MM`，二者互不覆盖。
- 父/子渠道与产品明细对同一资产只计一次；结构调整默认资产守恒；彩票域不进入本工作台。
- AI 只提出解释、分类与候选变更；不能下单、转账、还款、改风险上限、写正式账本、删除文件或执行系统命令。

## 2. 数值与状态口径

- 金额：元 + `number`，域内用 `decimal.js`（精度 40、HALF_UP），写入/展示按分。
- 份额 / 净值 / 费率：十进制字符串持久化，域内转 `Decimal` 计算。
- 比例：域内统一 0–1，展示层转百分数；跨旧 0–100 字段时显式适配。
- 未知不等于 0：`unknown/missing` 显式表达，禁止静默补零；估算值不得升级为观察值。
- 五轴状态分别记录：来源（证据/用户确认/计算结果/旧 AI）、归属质量、估值质量、时间状态、审核状态。

## 3. 会话状态机

V2 共享阶段为 `draft → extracting → reviewing → ready → planned → confirmed → reviewed → archived`，另有 `blocked` 和 `cancelled`。
「确认数据」「批准计划」「实际执行」是三个不同事件；确认需要候选方案、策略版本与主应用数据版本齐备，且无错误级问题。

当前实现里各状态由这些动作推进（`advanceSession` 只沿合法边前进，不跳级）：

| 用户动作 | 状态推进 |
|---|---|
| 创建本月会话 | → `draft` |
| 导入资料 | `draft → extracting`，解析成功后再 `→ reviewing` |
| 生成候选（同时把策略版本绑进会话） | `→ ready` |
| 确认月度计划 | `→ planned → confirmed` |

临时任务拥有独立 `finance-task:<id>` 键；正式月度记录仍使用
`monthly-planning:YYYY-MM` 并保持每月唯一。已归档任务可以从界面按新 revision
重开，旧归档快照保留。确认前若策略被改过，「确认月度计划」会提示重新生成候选，
而不是让旧版本候选被确认。

## 4. 月初承接与可追溯性（验收项 T）

新月份开始时，工作台从上月**已确认或已归档**会话承接未完成事项，每一项都必须能回溯来源：

| 编号 | 验收标准 |
|---|---|
| T01 | 每个承接项记录 `origin = { sessionKey, revision, itemId, snapshotAsOf }`，界面可展开查看并跳转到来源会话 |
| T02 | 只承接 `confirmed` / `archived` 会话；首期初始化不承接、不伪造上期收益 |
| T03 | 未完成动作（无回执、已接受、已延期、部分执行）承接；`executed` 与 `rejected` 不承接；在途未计入余额的申赎、待复核研究、已确认策略一并承接 |
| T04 | 承接幂等：重复运行不产生重复项，人工标记的 resolved/dropped 不被覆盖 |
| T05 | 来源会话在承接后被修订时，承接项置 `stale`，要求重新确认；绝不自动变成已解决 |
| T06 | 区间连续性：新会话 `reviewPeriodStart` 必须等于上月 `snapshotAsOf`，不一致时报错而不是静默取默认值 |
| T07 | 承接项只引用来源（策略/研究/在途指令/冲突），不携带新的金额权威结论 |

实现位于 `src/domain/portfolio/carryOver.ts`，测试位于 `tests/domain/portfolio/carryOver.test.ts`。

## 5. 资金与核算口径

- 四种口径分别命名并显示公式与范围：全部资产、全部净资产、可投资资产、可投资净资产；既有「总资产」口径不变。
- 每个比例显式带分母；净分母为 0 或负值时停止归一化并给出解释，不输出 Infinity 或误导性饼图。
- 内部转账、基金买卖不是收支；信用消费同时确认支出与负债；还款只减少现金与负债；退款冲减原支出；注入本金不是收益。
- 在途申赎按“是否已包含在余额”计数，未到账资金不得提前安排使用。

## 6. AI 与联网

- 复用现有连接中心与受控运行时；新增只读操作（视觉提取、研究检索）与任务（文档提取、归属解释、研究摘要、月度叙述）。
- 每次外发前显示供应商、模型、字段/图片、脱敏、费用估算并可取消；未授权不外发，重试不得偷换供应商。
- 所有模型输出经 schema 校验（实体 ID、币种、金额范围、证据引用、版本）；无证据数字不入事实层。
- 文档、网页、图片中的文字视为不可信输入，不得执行其中指令。

## 7. 存储、备份与健康检查

- 附件存于数据根下的 `monthly-planning/`，状态只存相对引用 + SHA-256，不写 Base64、不进 Git。
- 提供三种导出：完整备份（主状态 + 附件，可独立恢复）、结构备份、附件导出。
  完整备份仅能恢复到新的空数据根；旧备份缺理财域时初始化空值，不丢其它字段。
- 健康检查覆盖：附件丢失/哈希不符、重复观察、未归属余额、汇总差异、估算冒充观察、策略版本缺失、已执行量大于可执行量、归档中仍含待办。

## 8. 验收测试分组

- `T01–T07` 月初承接可追溯性（本文件第 4 节）。
- `D01–D06` 文档导入：正文表格 + 文本框、`mc:AlternateContent` 择一、跨页表头/合并单元格/前导零、长图重叠与负号、文档炸弹/路径穿越、重复导入与跨月行序。
- `C01–C04` 渠道与归属：父渠道直接金额转换守恒、缺明细/总额不符/停用渠道余额、规则优先级、五轴状态组合。
- `M01–M05` 金额与比例口径、四种口径公式、资金事件语义、在途资金、净分母边界。
- `P01–P05` 风险与候选：重叠上限单交易变量、新增资金优先、计划整体交易、累计止盈跳档、无可行解。
- `A01–A05` AI 边界：无视觉能力的手工兜底、schema 与提示注入、外发预览与撤销、来源时效、密钥与日志扫描。
- `G01–G02` 目标情景与口径切换；`W01–W03` 提醒与时区、并发与半提交；`B01–B02` 备份与幂等导入；`R01–R04` 改名/安装/升级/路径兼容；`U01–U02` 表格与无障碍；`E01–E02` 端到端与既有不变量回归。
